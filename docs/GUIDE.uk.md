# Посібник FormaTranslate

[English overview](../README.md) · [Завантажити](https://github.com/grebocheck/FormaTranslate/releases/latest)

Власний desktop-застосунок для перекладу **DOCX, XLSX та PDF** через OpenAI, Gemini, Anthropic Claude або сумісний API. Скановані PDF спочатку розпізнаються локально у DOCX. Пріоритет — якість перекладу й збереження структури документа.

Стек: Python 3.12, PySide6 / Qt Quick, точкове редагування OOXML, окремий PDF-рушій BabelDOC.

Linux-пакет 0.3.0 потребує **glibc 2.43 або новішої** (зібрано на Ubuntu 26.04). Для старіших дистрибутивів запускайте з вихідного коду або збирайте на цільовій системі.

## Швидкий запуск

Готовий застосунок постачається як портативна папка у ZIP. **Розпакуйте весь архів** і запустіть **`Forma-windows-x86_64.exe`** для Windows або **`Forma-linux-x86_64`** для Linux з його кореня; кандидатні Windows-збірки мають позначку `candidate` у назві. Зберігайте папку `_internal` та всі інші файли разом із виконуваним файлом — переносити лише EXE не можна. Відкрийте **Налаштування**, введіть адресу API, модель і ключ та натисніть **Зберегти**. Встановлювати Python або створювати `.env` не потрібно. Єдиний Windows-пакет містить BabelDOC, OCR, моделі й Tesseract; Linux використовує окремо встановлені PDF/OCR-рушії. Бібліотеки та моделі завантажуються з уже розпакованої папки без повторного розпакування великого EXE на кожному старті.

Для перекладу мовною моделлю на власному ПК встановіть окремий сервер **LM Studio** або **Ollama**, а у налаштуваннях Forma виберіть **LM Studio (локально)** чи **Ollama (локально)** й встановлену модель. Пресети лише заповнюють параметри підключення; сервер і модель завантажуються окремо від Forma. Покрокова інструкція: [локальний AI — встановлення й налаштування](LOCAL-AI.uk.md).

Для запуску з вихідного коду потрібен [uv](https://docs.astral.sh/uv/getting-started/installation/):

```sh
uv sync
uv run forma
```

Основний сценарій: додайте документи, виберіть мову й натисніть **Перекласти**. Файли можна перетягувати у вікно або додавати через `Ctrl+O`. Вікна вибору файлів використовують стандартний діалог ОС, якщо він доступний, або стандартний Qt Widgets діалог без палітри застосунку. Готовий документ відкривається зі списку. Редактура й узгодження термінології ввімкнені; тематика та CSV-глосарій доступні під **Параметри перекладу**.

Навігація розділена на вкладки **Документи**, **Текст і фото**, **Перевірка**, **Історія** та **Налаштування**. Кнопки мають іконки, текстові підписи й видимий фокус клавіатури. У налаштуваннях змінюються адреса API, модель, ключ, окрема модель редактора, режим API та формат відповіді. Окремий блок **Швидкість і ліміти** містить паралельність, час очікування, ліміт токенів і рівень міркування. **Перевірити підключення** зберігає введені значення й виконує короткий API-запит, який може тарифікуватися провайдером.

**Перевірка** має власний вибір документа, пошук, режими **Зауваження** та **Увесь текст**. Список ліворуч об’єднує повідомлення за фрагментами; праворуч оригінал і переклад можна читати та копіювати поруч. Кнопки переходу ведуть до наступного або попереднього фрагмента. Перевірку можна відкрити також з історії, не додаючи документ у чергу повторно. Збережені звіти перевіряються поточними локальними правилами без API-запитів; самі старі HTML/JSON-звіти не перезаписуються, тому можуть містити попередні зауваження.

Під час перекладу DOCX/XLSX з увімкненою редактурою програма може сама виконати ще один обмежений прохід виправлення: для залишків прози мовою оригіналу, нових повторів, підозріло короткого перекладу та неперекладених підписів між мовами з різними абетками. Цей прохід входить у наявний ліміт спроб редактури. Якщо новий варіант не проходить перевірку або не покращує ці зауваження, зберігається попередній допустимий текст. Попередження, які залишилися, не приховуються й не позначаються автоматично як підтверджені людиною.

Збережений машинний переклад із такими зауваженнями може перейти одразу до редактора без нового початкового перекладу. Завершену спробу програма запам’ятовує для того самого тексту, контексту та налаштувань; явно затверджені людиною формулювання проєкту зберігаються. Додаткова редактура використовує налаштований API і тарифікується провайдером; якщо редактуру вимкнено, цього додаткового проходу немає. Саме відкриття перевірки, перемикання записів і локальні підтвердження не запускають редактора чи API-запитів.

У перевірці можна натиснути **Це коректно**: запис зникне з активних зауважень, залишиться позначеним у режимі **Увесь текст**, де підтвердження можна скасувати. Рішення зберігається для точного вмісту фрагмента та його повідомлень; зміна звіту або тексту вимагає нового перегляду. Критичні помилки чисел, кодів і форматування не можна приховати цією кнопкою. Ця дія не затверджує формулювання для пам’яті перекладів.

Для DOCX/XLSX доступне **Редагувати**. **Зберегти правку** біля тексту перекладу перевіряє зміни та зберігає їх як локальну чернетку; **Скасувати** залишає попередній текст. **Зберегти копію** створює окремий `.reviewed.docx` або `.reviewed.xlsx` і нові звіти, додає результат до історії. Оригінал і попередній переклад не перезаписуються. У меню **Інші дії** можна скасувати збережену правку до експорту. Поки курсор у редакторі, **Ctrl+Enter** зберігає правку; у модальному вікні ця комбінація не застосовується. Коли виправлене зауваження зникає зі списку, вибирається наступний запис поруч, а не початок списку. При закритті введений коректний текст зберігається як чернетка; якщо він не проходить перевірку, спочатку виправте або скасуйте його. Усі ці дії локальні й не виконують API-запитів.

Експорт редактури використовує наявний переклад: стилі, таблиці, формули й службові елементи зберігаються. Зміни інших фрагментів у зовнішньому редакторі переносяться у копію, якщо структура сумісна й валідація проходить. Зміна редагованого фрагмента, структури або оригіналу після створення звіту зупиняє експорт. Для редактури потрібні оригінал, переклад і звіт Forma. Кількість переносів, які позначають службові елементи, змінювати не можна. Ручне редагування PDF поки недоступне; його зауваження можна підтверджувати.

Примітка **Track Changes** означає, що у Word є історія виправлень. Поточний видимий текст перекладено, а позначений як видалений збережено мовою оригіналу. Це інформація про документ, а не помилка перекладу. Відновлений у Word видалений текст потребуватиме окремого перекладу. Кнопка **Це коректно** у Forma не приймає та не відхиляє виправлення Word.

Перевірка позначень додатків зіставляє явні заголовки DOCX. Вона повідомляє, якщо один додаток отримав різні літери або різні додатки мають однакові чи візуально однакові позначення, наприклад латинську `B` і кириличну `В`. Перевірте пов’язані записи у змісті й заголовках через пошук та узгодьте правки. Програма не перенумеровує додатки самостійно й не блокує експорт через цю евристику. Зміна іншого пов’язаного заголовка скасовує попереднє підтвердження такого зауваження. Перевірка не є повною валідацією всіх закладок, посилань у прозі та піддодатків.

Нові запити перекладачу й редактору вказують зберігати літери додатків з оригіналу. Якщо потрібна інша узгоджена схема позначень, задайте відповідники у власному глосарії. Готові сумісні переклади продовжують використовуватися з кешу; відкриття перевірки не оплачує їх повторну генерацію.

**Діаграми й зображення потребують окремого контролю.** Текстові кеші назв рядів і категорій вбудованих діаграм Word поки зберігаються без перекладу; для виявлених текстових підписів новий переклад містить попередження. Текст у пікселях зображення також не входить у звичайний Office-переклад: інформаційна примітка не означає, що написи є на кожному зображенні. Перевірте графіки у Word та, за потреби, перекладіть їхні підписи окремо. Числа діаграм, вбудовані книги та самі зображення не переписуються. Старі звіти без цих приміток не підтверджують повноту перекладу графіки.

Після перекладу перевірте зміст і номери сторінок після оновлення полів у Word. Довжина перекладу, доступні шрифти та інший редактор можуть змінити розбиття на сторінки; автоматичні перевірки структури не підтверджують точність пагінації.

Звичайні банери успішного завершення прибрано: стан видно біля документа. Помилки й повідомлення, які потребують дії, залишаються. Службові примітки про поля Word, збереження назв аркушів і формул XLSX та спосіб обробки PDF відокремлено від зауважень; вони доступні в режимі **Увесь текст**. Незмінні міжнародні позначення, формули та коди обладнання не вважаються пропущеним перекладом лише через збіг тексту; звичайна проза та кириличні терміни перевіряються далі.

Ключ показується маскованим під час введення; після збереження поле очищується. Порожнє поле залишає поточний ключ. **Запам’ятати ключ** використовує Windows Credential Manager або Linux Secret Service. Ключ прив’язаний до адреси API, не записується у `preferences.json` і не переноситься автоматично до іншого провайдера. Якщо системне сховище недоступне, програма явно повідомить, що ключ діє лише до закриття. Без прапорця ключ використовується тільки в поточній сесії. Видалення ключа застосовується кнопкою **Зберегти**.

Параметри й папка результатів зберігаються у профілі користувача, окремо від виконуваного файла. `.env` і змінні середовища залишаються необов’язковим способом первинного налаштування: збережені в застосунку параметри мають пріоритет. Видалений або сесійний ключ не відновлюється автоматично зі старого `.env`. Явний CLI-параметр `--env шлях` використовує вказаний файл і змінні середовища замість налаштувань застосунку. Для локального сервера без авторизації ключ може бути порожнім.

## Gemini та Anthropic Claude

У **Налаштуваннях** оберіть пресет **Google Gemini — Free Tier**, **Google Gemini** або **Anthropic Claude**, введіть відповідний API-ключ і збережіть. Пресет заповнить адресу, модель, протокол і ліміти; усі параметри можна змінити. Сам вибір пресета не надсилає запитів. Ключ іншого провайдера не переноситься.

Gemini Free Tier починає з `gemini-3.5-flash-lite`: один запит одночасно, один документ і до п’яти запитів за хвилину. Це локальне обмеження темпу, а не гарантована квота Google. Free Tier залежить від проєкту Google AI Studio; вибір пресета **не вимикає оплату** в платному проєкті. Редактура, глосарій, повторні спроби й перевірка підключення також витрачають квоту. Денний ліміт може бути малим для великих документів. За вичерпаної квоти програма не перемикає модель або тариф автоматично.

Безплатний сервіс Gemini може використовувати надісланий вміст для покращення продуктів Google; перевірте умови свого проєкту перед роботою з конфіденційними даними. [Ключі Google AI Studio](https://aistudio.google.com/apikey), [ліміти](https://ai.google.dev/gemini-api/docs/rate-limits), [умови](https://ai.google.dev/gemini-api/terms).

Claude використовує власний Messages API та API-ключ Anthropic. Доступ, кредити й оплату визначає ваш API-акаунт. Нові протоколи доступні для документів, тексту, фото та PDF через окремо встановлений BabelDOC. [Докладніше про підключення](PROVIDERS.md).

## Текст і фото

Вкладка **Текст і фото** має два режими. Для тексту вставте або введіть до 20 000 символів, виберіть мови й натисніть **Перекласти**. Виконується переклад із редактурою, зберігаються переноси, числа, посилання та коди. Результат можна скопіювати.

Для фото виберіть файл, перетягніть його або натисніть **Вставити фото** / **Ctrl+V**. Надсилання до API починається лише після **Перекласти**. Потрібна модель із підтримкою зображень. Доступні оригінал і переклад, збільшення, розпізнаний текст, копіювання фото та **Зберегти PNG**. Оригінальний файл не змінюється.

Написи розпізнає vision-модель, а застосунок накладає переклад локально. На складному фоні можливі однотонні підкладки; точність дрібних або повернутих написів і координат залежить від моделі. Якщо текст не вміщується або ділянки перекриваються, відповідна частина лишається оригінальною з поясненням; повний переклад доступний поруч. Перевіряйте оригінал і розпізнаний текст.

Текст і фото не записуються в історію та не кешуються автоматично. Ліміти фото: 30 МБ, 24 мегапікселі, 20 000 пікселів на сторону. До API надходить зображення без метаданих, зменшене до 2048 пікселів на сторону / 2 мегапікселів; PNG-результат зберігає початкові розміри.

## Що працює

- Черга файлів зберігається між запусками. Файли можна додавати під час перекладу; для тих, що ще очікують, доступні зміна порядку та видалення з черги. Нові файли використовують налаштування поточного запуску. Якщо читання файла завершилося вже після спорожнення активної черги, він очікує наступного натискання **Перекласти**. Після перезапуску незавершені завдання самостійно не запускаються.
- **Історія** зберігає модель, мови, час, зауваження й результат кожної спроби. Звідти можна відкрити документ, його папку чи звіт, повернути оригінал у чергу з поточними налаштуваннями або прибрати лише запис історії. **Імпортувати з папки** читає попередні `.forma.json` з вибраної папки результатів та об’єднує дублікати. Видалення записів чи очищення завершених завдань не видаляє файли.
- Папку результатів можна відкрити прямо біля її шляху. Український GUI підтримує перетягування документів.
- У налаштуваннях є селектори основної моделі й редактора з ручним введенням. **Оновити моделі** виконує лише `GET /models` до введеної адреси API, без запиту перекладу й без збереження чернетки налаштувань. Ключ попереднього провайдера не передається новому. Список відображає те, що повертає провайдер: він може містити моделі, непридатні для текстового перекладу; автоматичне визначення їхніх можливостей не виконується.
- Паралельна обробка документів і фрагментів зі спільним обмеженням запитів до API. Типово: 2 документи та до 8 запитів одночасно; параметри змінюються в блоці **Швидкість і ліміти**. Раніше збережені користувацькі ліміти не перезаписуються. Однакові копії Office і файли з однаковими вихідними іменами обробляються послідовно, щоб узгоджено використовувати кеш і зберігати результати.
- Описові написи великими літерами з дефісом, як-от `IN-SERVICE` і `COST-BENEFIT`, також потрапляють у переклад; захищені коди обладнання зберігаються. Через зміну виділення фрагментів старі позиційні контрольні точки не перевикористовуються для нового протоколу.
- DOCX: абзаци, таблиці, змішані текстові стилі, посилання, колонтитули, виноски, коментарі, текстові блоки й доступні DrawingML-написи. Невідредаговані частини ZIP переносяться без зміни їхніх байтів.
- XLSX: текстові комірки, shared strings, rich text, примітки й доступні DrawingML-написи. Формули, числа, назви аркушів, стилі, зображення й зв’язки не переписуються.
- Контекст із початку, середини й кінця документа, а також сусідніх фрагментів. Для таблиць DOCX — рядок і перший рядок таблиці; для XLSX — назва аркуша, адреса комірки, сусідні підписи та значення. Повторювані shared strings отримують приклади різних використань.
- CSV-глосарій, автоматичний глосарій із термінів, присутніх у вибірці документа, окремий редакторський прохід. Модель отримує вимогу зберігати заперечення, обов’язки, умови, винятки та причинні зв’язки.
- Коди, адреси, назви файлів і змінні захищаються підстановками до перекладу та редактури й відновлюються перед записом.
- За явно заданої мови оригіналу з десятковою комою й перекладу англійською десяткові крапки узгоджуються у тексті та числових текстових комірках DOCX. Захищені коди й нативні числа XLSX зберігаються.
- Валідація форматувальних позначок, чисел, URL, змінних і кодів. Якщо результат не проходить перевірку після трьох спроб, експорт зупиняється.
- Контрольні точки окремо зберігають валідовані чернетки й відредаговані фрагменти. Повторний запит виправляє лише фрагменти, які не пройшли перевірку, включно з пропущеними чи дубльованими ID у відповіді моделі. Після зупинки вже отримані коректні відповіді зберігаються, нові запити не запускаються; перервана редактура продовжується без повторного перекладу чернеток.
- Для явно заданих пар мов із латиницею та кирилицею позначаються довгі фрагменти, які можуть залишатися мовою оригіналу. Це попередження для перегляду: бібліографія та офіційні назви можуть законно залишатися незмінними. Перевірка письма не визначає мову довільного тексту й не вимірює точність перекладу.
- Попередження про нові повтори довгих слів або фрагментів після перекладу чи редактури. Текст не видаляється автоматично; наявні повтори оригіналу враховуються.
- HTML/JSON-звіти, облік токенів Office-перекладу, локальне порівняння структури через CLI для досліджень.
- Chat Completions і Responses API. Режим `auto` пробує JSON Schema, JSON mode, потім звичайний JSON, коли провайдер явно повідомляє про непідтримуваний формат.

Пауза й зупинка застосовуються після поточного API-запиту; для зовнішнього PDF-процесу зупинка завершує процес, а пауза діє перед наступним файлом. Під час закриття програма очікує завершення поточного запиту.

Паралельність не вимикає редактуру: кожен пакет проходить переклад, перевірку й потрібні виправлення перед експортом. Перевірені фрагменти записуються в контрольні точки. Помилка одного документа не зупиняє решту черги. Для Office відповідь HTTP 429 встановлює спільну паузу запитів відповідно до `Retry-After`; зовнішній PDF-рушій обробляє свої повтори самостійно. Ліміт запитів діє для всієї черги, включно з робочими потоками PDF, а не множиться на кількість файлів. Він обмежує одночасні запити, але не замінює квоти провайдера на токени/хвилину. Для великих PDF зменште кількість одночасних документів до 1, якщо бракує пам’яті.

## Глосарій: коли потрібен і як почати

Глосарій — ваш список термінів і бажаних перекладів: наприклад, назва установи, технічне поняття чи узгоджене скорочення. **Він необов’язковий**. Переклад працює з порожнім списком; шукати готовий файл в Інтернеті не потрібно. Можна взяти вже погоджені терміни замовника або створити початковий список із власних документів.

У **Документах** натисніть **Глосарій (необов’язково)…**:

1. **Додати термін** створює рядок із полями **Термін оригіналу** та **Бажаний переклад**. Їх можна редагувати й видаляти без API.
2. Або додайте DOCX/XLSX до черги й натисніть **Запропонувати з документів**. Програма надішле обмежені уривки налаштованому AI-провайдеру; цей запит оплачується за його тарифом. Саме відкриття вікна нічого не надсилає.
3. Перевірте запропоновані терміни, приберіть зайве та виправте переклади. Наявні бажані переклади не замінюються автоматично. Натисніть **Застосувати глосарій**, щоб список почав діяти.

До застосування це чернетка. Закриття й повторне відкриття вікна в тій самій сесії зберігає її; **Скасувати правки** повертає застосований список. У проєкті глосарій зберігається для наступних запусків програми, без проєкту — використовується для поточної черги. Розділ **CSV… → Імпортувати CSV / Експортувати CSV** потрібен лише для перенесення списку. Імпорт додає терміни до чернетки, зберігаючи наявні переклади; він також потребує **Застосувати глосарій**.

Без пам’яті проєкту параметр **Автоматично добирати терміни для документа** може підбирати їх під час перекладу. Це додатковий API-запит. Автоматичні варіанти — підказки: модель має враховувати контекст кожного вживання, наприклад різні значення слова в технічній і фінансовій таблицях. Власні застосовані терміни мають пріоритет і залишаються обов’язковими. У проєкті використовується один спільний застосований список, щоб окремі документи не отримували різні автоматичні глосарії.

Глосарій узгоджує термінологію; повні повторювані абзаци зберігає пам’ять перекладів. Повідомлення про змінені числа не означає, що бракує глосарія, і глосарій не вимикає перевірку чисел, кодів чи форматування.

Якщо переклад зупинився після повторних спроб виправлення, виберіть документ у черзі й натисніть **Виправити й продовжити**. Відкриється **Перевірка** з проблемними фрагментами: звірте оригінал з останнім варіантом перекладу, натисніть **Редагувати**, виправте текст і **Зберегти правку**. Перевірки чисел, кодів і форматування діють також для ручних змін; кнопка **Це коректно** не приховує критичні помилки. Якщо нові правила вже визнають останній варіант коректним, його можна використати без переписування.

Натисніть **Продовжити переклад**: програма перевірить правки й відновить саме цей документ із параметрами перерваного запуску. Готові сумісні фрагменти та ваші виправлення використовуються повторно. Якщо лишилися неперекладені фрагменти, для них можуть виконуватися нові API-запити. До продовження правки зберігаються локально й доступні після перезапуску, поки документ залишається в черзі. Зміна оригіналу, звіту або несумісних налаштувань зупиняє відновлення; вихідний файл не перезаписується.

**Переглянути помилки** відкриває окремий локальний HTML-звіт з абзацом, оригіналом, останнім варіантом і відмінностями чисел. Це діагностика незавершеного перекладу; некоректний DOCX не експортується. Якщо звіт не підтримує ручне продовження, повторіть переклад зі сторінки **Документи**: сумісні готові фрагменти з контрольної точки використовуються повторно. Для PDF після OCR виправляється текст підготовленого DOCX, а продовження також перевіряє вихідний PDF. Звіт і локальні правки містять текст документа й мають залишатися приватними.

## Пам’ять перекладів проєкту

Для пов’язаних DOCX/XLSX виберіть явні мови оригіналу й перекладу, потім **Пам’ять проєкту → Створити проєкт…**. Введіть назву або виберіть уже створений проєкт із такою самою мовною парою. Початковий стан — **Вимкнено**: звичайний переклад працює без проєктної пам’яті.

Для початку достатньо назви й мов: пам’ять поповнюється автоматично після перекладу. **Глосарій та еталони необов’язкові**. **Глосарій (необов’язково)…** або **Еталони й глосарій… → Редагувати терміни…** відкриває спільний список проєкту. У режимі пам’яті окремі автоматичні глосарії документів вимкнені: черга використовує один зафіксований глосарій. Зміни діють для наступного запуску. Після вимкнення пам’яті знову застосовуються звичайні параметри глосарію.

Повторне використання без API потребує точного збігу тексту з форматувальними позначками, контексту, ролі фрагмента й правил перекладу: мов, тематики, власних інструкцій, глосарію та числової конвенції. Незмінний напис в іншій таблиці або серед інших сусідніх абзаців може потребувати нового перекладу. Зміна імені, числа чи заперечення не є точним збігом.

Завершені машинні переклади перевикористовуються за сумісних налаштувань генерації. Чернетка може продовжити редактуру, але не вважається готовим перекладом. У межах однієї черги однакові точні записи використовують спільний результат; окремі процеси застосунку можуть виконати повторні запити.

Якщо ввімкнено редакторську перевірку, для достатньо довгого близького фрагмента програма може взяти завершений переклад із пам’яті як основу. Власний текст має змінитися, а повний навколишній контекст — лишитися незмінним; правила, роль і форматувальні позначки мають бути сумісними. Модель отримує весь новий оригінал із поточним контекстом, попередній оригінал і переклад та перелік змін. Початковий запит перекладу пропускається, але адаптація й двомовна перевірка потребують API-запиту. Імена, числа, одиниці та заперечення перевіряються за новим оригіналом; механічної підстановки немає. Без редакторської перевірки або придатного кандидата виконується звичайний переклад. Зміна контексту, зокрема поза видимим уривком, також вимагає звичайного перекладу; змінений текст таблиць DOCX наразі проходить цей шлях. Адаптований результат лишається машинним, навіть якщо попередній варіант був затверджений людиною; схожість не є оцінкою точності.

Якщо вже є перевірений переклад, у **Еталонах й глосарії…** розгорніть **У мене вже є перевірений переклад (необов’язково)**. Виберіть оригінальний DOCX, перекладений DOCX і відповідний `.forma.json`, потім **Додати еталон**. Файли та прив’язки фрагментів перевіряються локально, без API. Без позначки **Я перевірив цей переклад: використовувати його формулювання в проєкті** записи лишаються довідковими й автоматично не підставляються. Позначка — явне затвердження всього сумісного імпорту; глосарій і мови мають відповідати проєкту. Старий звіт із невідомим ефективним автоматичним глосарієм можна додати лише як довідковий. Після виправлень у Forma використовуйте **Зберегти копію** та новий звіт саме до цієї копії.

Для окремого фрагмента DOCX у **Перевірці** є **Інші дії → Запам’ятати формулювання → Використовувати в проєкті**. Коректну застосовану чернетку можна запам’ятати до експорту Office-копії; поточні файли та позначки перевірки не змінюються. Якщо вже є інший затверджений варіант, порівняйте попереднє й нове формулювання та окремо натисніть **Замінити формулювання**. Зміна пам’яті чи глосарію під час цього діалогу потребує повторного перегляду.

Затверджене формулювання має пріоритет над старими машинними варіантами й контрольними точками в наступних запусках. Поточна черга використовує редакцію пам’яті, зафіксовану на її початку. У звіті окремо обліковуються контрольні точки, проєктна пам’ять, повтори в межах запуску та адаптовані фрагменти. Адаптація може витрачати токени; ці лічильники не є оцінкою мовної якості чи гарантованим відсотком економії.

Пам’ять абзаців підтримує DOCX/XLSX, а імпорт еталонів і запам’ятовування формулювань — DOCX. PDF можна залишати в тій самій черзі з увімкненою пам’яттю: текстові PDF використовують глосарій проєкту без повторного використання абзаців, скани автоматично проходять OCR у DOCX й перекладаються зі спільною пам’яттю. Проєкт залишається активним. Автоматичне вставлення неточних збігів без API-перевірки, довільні шаблони зі змінними та обмін TMX поки не реалізовані. Докладні правила й CLI: [Project translation memory](TRANSLATION-MEMORY.md).

## PDF

Додайте PDF, виберіть мови й натисніть **Перекласти**. Програма сама обере прямий переклад текстового PDF через BabelDOC або підготує скан у DOCX через OCR і продовжить переклад. Мови, налаштування та пам’ять фіксуються на початку завдання. **Зупинити** скасовує весь ланцюжок; після перезапуску програма не починає платні запити самостійно.

Якщо вибрано звичайний ABBYY, збережіть і перевірте DOCX у його редакторі, а потім натисніть **Імпортувати й продовжити**. Повторне натискання «Перекласти» не потрібне. Для окремої підготовки й виправлення OCR до перекладу є **Додаткові дії з PDF → Скан PDF → DOCX**. Оригінальний PDF зберігається; звіт пов’язує його з розпізнаним DOCX, на якому працюють редактура й збереження виправленої копії.

Windows уже містить BabelDOC та його ресурси. Для Linux або запуску з коду BabelDOC встановлюється **окремо**, у власне середовище:

```sh
uv tool install --python 3.12 BabelDOC==0.7.1
babeldoc --warmup
```

Якщо команда недоступна в PATH, вкажіть повний шлях у налаштуваннях або `FORMA_BABELDOC_PATH` у `.env`. Типовий Linux-шлях: `~/.local/bin/babeldoc`. Підтримувані параметри інтеграції описані в [офіційному README BabelDOC](https://github.com/funstory-ai/BabelDOC).

Інтеграцію перевірено з BabelDOC 0.7.1, включно зі створенням PDF через локальний імітатор API. Повторити перевірку: `uv run python scripts/smoke_pdf.py`. Вона не оцінює мовну якість і не використовує платний API.

Під час обробки відображаються фактичні етапи BabelDOC: аналіз верстки, таблиці, термінологія, переклад абзаців, шрифти та збереження. Forma читає стандартний прогрес CLI 0.7.1; якщо рушій тимчасово не повідомляє прогрес або змінить формат журналу, показується минулий час без вигаданих відсотків. Перший запуск може завантажувати моделі та шрифти; `babeldoc --warmup` готує їх заздалегідь. Паралельність прискорює запити до API, але не усуває час локального аналізу PDF.

Для прямого PDF-перекладу виберіть **мову оригіналу**. Підтримуються режими API `chat`, `gemini` та `anthropic`; `responses` для цього маршруту не підтримується. Forma застосовує налаштовані timeout, reasoning effort та ліміт вихідних токенів до запитів BabelDOC через тимчасовий локальний адаптер. Для reasoning-моделей `max_tokens` перетворюється на підтримуваний `max_completion_tokens`: без цього BabelDOC 0.7.1 міг отримати HTTP 400 і експортувати вихідний англійський текст. Постійні помилки API та обірвані відповіді тепер зупиняють експорт. Нульовий ліміт токенів залишає автоматичну поведінку рушія; для довгих відповідей може знадобитися явний більший ліміт.

BabelDOC отримує лише одноразовий локальний токен; справжній API-ключ залишається в пам’яті Forma і не передається в аргументах або TOML дочірнього процесу. Кеш PDF розділено за провайдером, моделлю, рівнем міркування й лімітом токенів; випадкова локальна адреса не скидає кеш. Поряд із PDF зберігається `.api.json` із кількістю запитів, затримкою та токенами з отриманих API-відповідей; кешовані й перервані зовнішні запити можуть не мати даних про використання.

Forma перевіряє кількість і розміри сторінок, відсутній текст та дуже великі втрати текстового шару. Якщо при перекладі між латиницею й кирилицею весь зміст залишається вихідною писемністю, результат відхиляється. Порожні й ілюстровані обкладинки дозволені; окремі незмінені сторінки й написи у зображеннях позначаються у звіті. Ці перевірки не доводять точність чи повноту перекладу та не визначають мову в межах однієї писемності. Форматування PDF потрібно оцінювати візуально.

Для сканованих і змішаних PDF **Перекласти** автоматично готує DOCX через вибраний локальний OCR-рушій і продовжує Office-переклад із тими самими мовами, глосарієм та пам’яттю. Початковий PDF залишається у черзі; звіт містить прив’язку до розпізнаного DOCX. Окреме розпізнавання доступне в додаткових PDF-діях, якщо хочете спочатку перевірити й виправити OCR. Для Linux або запуску з коду встановіть рушій командою `uv tool install --python 3.12 --torch-backend cpu ./tools/ocr`; повний Windows-пакет містить його моделі. Виберіть явну мову оригіналу OCR: англійську, українську, польську або німецьку. Розпізнавання не використовує платний API; подальший переклад звертається до налаштованої мовної моделі. Для звичайних редакцій ABBYY може знадобитися перевірений ручний експорт DOCX; це пояснює відповідний сценарій. Сам PDF не змінюється. Розпізнаний DOCX, текст і таблиці потрібно звірити зі сканом. Основний локальний конвеєр використовує Docling, RapidOCR і TableFormer; встановлення LM Studio чи Ollama його не замінює.

Це відновлення редагованої структури, а не гарантія верстки піксель у піксель чи рівності ABBYY. Шрифти, рукописні написи, печатки, об’єднані комірки та таблиці через межу сторінок потребують перевірки. Непорожня сторінка без розпізнаного тексту зупиняє експорт. Обмеження — 200 МБ / 200 сторінок; повна інструкція й CLI: [PDF.md](PDF.md).

Редакторський прохід Forma застосовується до DOCX/XLSX; прямий PDF-переклад використовує власний процес BabelDOC. Повна Windows-збірка включає BabelDOC, OCR, локальні моделі та Tesseract; вони знаходяться автоматично й мають власні ліцензії. Для Linux і запуску з вихідного дерева рушії встановлюються окремо. Підготовка повного пакета: [WINDOWS-RUNTIME.md](WINDOWS-RUNTIME.md).

## Межі підтримки

- Немає вбудованого WYSIWYG-переглядача Office. Ручні текстові правки DOCX/XLSX доступні у перевірці; кінцеву верстку слід переглянути у Word, LibreOffice або іншому редакторі.
- Порядок текстових стилів усередині абзацу фіксований. Модель розподіляє переклад між наявними стилями; складні випадки потребують перевірки.
- Не перекладається текст у зображеннях, SmartArt із недоступним текстом, кешах діаграм, назвах аркушів і вбудованих файлах. Коди полів Word, поля дат і номерів сторінок зберігаються; видимий текст змісту та посилань TOC/REF перекладається. Видалений текст Track Changes зберігається.
- XLSX не змінює висоту рядків чи ширину стовпців. Довший переклад може візуально обрізатися.
- Старі XLSX-звіти можуть групувати клітинки зі спільним текстом. Нові переклади враховують кожне вживання окремо, тому виправлення однієї клітинки не змінює інші. Перевіряйте актуальність звіту до конкретного файлу.
- Розриви сторінок, шрифти та переноси залежать також від Office/LibreOffice і встановлених шрифтів. Збережена структура не означає ідентичну пагінацію.
- Зашифровані файли, підписані пакети Office і Strict OOXML не підтримуються. Документ не перезаписується; новий результат отримує окреме ім’я.
- Реальні API-випробування на приватних документах зберігаються локально в `output/`. Автоматичні структурні перевірки та вибіркова мовна перевірка не є сертифікацією якості всього документа.

Черга та історія зберігаються локально в `library.sqlite3` у папці даних застосунку: лише шляхи та метадані, без текстів документів і API-ключів. Вкладка історії показує останні 1000 записів. Проєктна пам’ять — окрема приватна база `translation-memory.sqlite3`: вона містить двомовний текст, контекст, глосарії та історію затверджень. Її вимкнення або очищення історії не видаляє записів пам’яті. Користувацькі бази не входять до релізних пакунків. Документи, глосарії, контрольні точки й звіти зберігаються локально. Текст і контекст надсилаються налаштованому AI-провайдеру. Підтвердження й ручні чернетки зберігаються окремо в `reviews/` у папці даних. Чернетки містять відредагований текст, прив’язаний до контрольної суми звіту; API-ключі в них не записуються. Локальні контрольні точки містять текст; видаляйте їх у папці даних застосунку, якщо вони більше не потрібні. Шлях можна перевизначити через `FORMA_DATA_DIR`.

## CLI та порівняння

```sh
uv run forma inspect examples/technical-brief.docx
uv run forma translate input.docx --target uk --output results
uv run forma translate input.xlsx --source en --target uk --glossary examples/glossary.csv
uv run forma compare input.docx results/forma.docx results/deepl.docx --report results/comparison
```

Порівняння доступне лише в CLI для дослідницьких перевірок і не використовує API. Метрики структурні: зміни нетекстових частин, формули, числа; для PDF — сторінки та їхні розміри. Це **не автоматичний бал точності перекладу**. Протокол порівняння: [docs/BENCHMARK.md](BENCHMARK.md).

## Розробка і збірка

Серія перевірок повторних запитів, чисел біля одиниць, кешу, скасування й паралельності без платного API:

```sh
uv run python scripts/research_pipeline.py
```

Невелике порівняння `default` / `low` / `none` на налаштованій моделі й синтетичних DOCX/XLSX:

```sh
uv run python scripts/research_translation.py          # лише підготувати файли
uv run python scripts/research_translation.py --live   # платні запити до налаштованого API
```

Звіти в `output/research/` містять оригінал, чернетку й редактуру, токени та структурні перевірки. Оцінювання змісту відокремлене від перевірок структури, відповідно до [рекомендацій OpenAI щодо evals](https://developers.openai.com/api/docs/guides/evaluation-best-practices). Невеликий набір прикладів не доводить рівноцінність режимів для довільних документів; типовий рівень міркування моделі автоматично не знижується.

Відтворюваний тест швидкодії черги без платного API:

```sh
uv run python scripts/benchmark_parallel.py
```

Створює шість синтетичних DOCX, виконує переклад із редактурою через локальний сервер із затримкою 100 мс і порівнює послідовний режим із 2 документами / 4 запитами. Результати, перевірка структури, кількість запитів і токенів — у `output/performance/benchmark.json`. Це перевірка паралельності, а не вимір швидкості реальної моделі чи якості перекладу.

Для повторюваної перевірки основного рушія на невеликих технічних, договірних і фінансових прикладах:

```sh
uv run python scripts/check_quality.py
uv run python scripts/check_quality.py --live
```

Перша команда лише створює синтетичні DOCX/XLSX у `output/quality-check/input`. `--live` виконує платний переклад українська → англійська через налаштовану модель із редактурою та зберігає результати, текстові пари, структурні перевірки й використання токенів у `output/quality-check/`. Це матеріал для перевірки змісту, а не автоматичний бал професійної якості. Приватні файли з `input/` не змінюються.

Після відкриття перекладеного DOCX у Word оновіть поля та зміст: **Ctrl+A → F9**. Переноси та кількість сторінок можуть змінитися. Текст усередині растрових графіків і фотографій залишається оригінальним.

```sh
uv sync --group dev --group build
uv run pytest
uv run ruff check .
uv run python scripts/make_examples.py
uv run python scripts/build.py
```

Збірка створює у `dist/` папку `Forma-windows-x86_64/` або `Forma-linux-x86_64/` із виконуваним файлом у корені та залежностями у `_internal`, а також релізний ZIP з усім її вмістом. Перед Windows-білдом потрібен підготовлений і перевірений комплект за [WINDOWS-RUNTIME.md](WINDOWS-RUNTIME.md). Скрипт не копіює `.env` чи особисті налаштування. Для запуску й перенесення зберігайте весь комплект; нову версію розпаковуйте в окрему папку. Деталі та межі перевірки Windows-збірок через Wine: [docs/WINDOWS-BUILD.md](WINDOWS-BUILD.md). CI/CD не використовується. macOS ще не входить у перевірені платформи.

На Linux потрібні системні бібліотеки для Qt/xcb та OpenGL. Для headless-перевірки можна використати `QT_QPA_PLATFORM=offscreen` і `QT_QUICK_BACKEND=software`.

## Витрати та баланс

Кнопка **Витрати** у верхній панелі показує орієнтовні витрати за сьогодні й 30 днів, кількість запитів і токенів. Облік починається з версії 0.4.0 та охоплює лише запити Forma з поточним ключем і сервером: документи, текст, фото, PDF і перевірку підключення. Локальний кеш не витрачає токени; повторні запити враховуються окремо. Невідома вартість позначається явно. Кнопка **Деталі за моделями** розгортає витрати та читання/запис кешу для кожної моделі. Дрібні суми й зміни залишку видно до шести знаків після коми.

Для відомих моделей офіційного OpenAI API застосовується стандартний тариф. Для іншого сервера або моделі можна ввести три власні ціни за мільйон токенів: вхід, кешований вхід і вихід. Ціни впливають лише на нові запити. Податки, регіональні доплати та окрема оплата запису кешу не включені.

**Відкрити баланс OpenAI** веде в офіційний білінг: звичайний ключ не дозволяє отримати залишок кредитів через документований API. За бажанням введіть поточний баланс вручну — Forma відніматиме наступні розраховані витрати. Цей залишок орієнтовний: інші застосунки, поповнення та строк дії кредитів не враховуються. Якщо після введення балансу є запити без повної оцінки вартості, числовий залишок приховується. Порожнє поле прибирає ручний баланс.

Дані зберігаються локально в `usage.sqlite3`, окремо для кожного ключа й сервера, без API-ключів та текстів документів. [Докладніше про облік](COSTS.md).


## Власні інструкції

У документах натисніть **Власні інструкції**, а у вкладці тексту й фото — **Інструкції**. Запишіть потрібні терміни, правопис і стиль, наприклад: «ДОДАТКИ перекладайте як APPENDICES. Використовуйте британський правопис і формальний технічний стиль». Збережені правила діятимуть для наступних перекладів і редакторської перевірки. Порожнє поле вимикає їх. Ліміт — 8 000 символів.

Правила зберігаються локально, включаються у звіт перекладу та надсилаються вибраному AI-сервісу; ключі й паролі сюди вводити не потрібно. Зміна правил оновлює кеш наступного перекладу. Уже запущені завдання й готові документи автоматично не змінюються. Перемикання мови інтерфейсу зберігає текст правил.

У версії 0.5.0 також виправлено облік запису кешу OpenAI: він має окремий тариф. Старі записи не зберігали цю деталізацію, тому їхні суми лишаються неповними; відновити точні списання з них неможливо. Знак **≥** означає нижню межу оцінки, **≈** — орієнтовну суму. Актуальний баланс перевіряйте у білінгу OpenAI. Деталі формули — у [Costs and balance](COSTS.md).
