# Code organization

`src/forma` keeps the application entry points and separates implementation by responsibility:

| Package | Responsibility |
|---|---|
| `core` | Shared document/result models and public asset locations |
| `settings` | Provider configuration, preferences and native credential-vault access |
| `persistence` | Atomic file writes, document history and review drafts |
| `accounting` | Request, token and cost records |
| `localization` | Interface catalogs and Qt translation boundaries |
| `providers` | Provider requests, protocol adapters, presets and model discovery |
| `translation` | Office translation, validation, terminology, text/photo translation and reports |
| `documents` | Office structure, review/export, PDF and local OCR integration |
| `memory` | Project memory, frozen sessions, exact reuse and reviewed adaptation candidates |
| `presentation` | Qt controllers and focused desktop workflows |
| `ui`, `locales` | QML and the six interface-language catalogs |

`forma.app`, `python -m forma` and the `forma`/`forma-desktop` entry points remain stable. Internal Python imports use the packages above; there is no parallel set of legacy forwarding modules.

The presentation layer coordinates document work and exposes Qt properties and slots. Document parsing, provider calls and file discovery belong in background work; reading a QML property must not trigger repeated filesystem or network operations. Initial document inspection has a separate bounded queue: at most two parsers, respecting a lower document-concurrency setting. Removed or closing-window requests never start a waiting parse; already running parsers finish safely. Translation and memory reuse retain the ordinary formatting, number and identifier validators.

`RunContext` freezes settings, options and the output directory; `DocumentJob` captures a source and its PDF route when queued. `DocumentListModel` keeps stable row IDs and emits row-level insert, remove, move and progress changes, preserving delegates and selections. The facade retains a compatibility document snapshot for Python callers; Qt Quick uses the incremental model and focused summary properties. `DocumentWorkspace.qml` shares one document sidebar between Translation and Review; Settings, History and Text/photos remain separate destinations.

`presentation/session_workflow.py` owns the shared selection and document-specific review navigation. Its separate incremental workspace model combines queued documents with explicitly opened historical reports; opening a historical report never queues it for translation. `persistence/session_store.py` keeps bounded local session metadata in `workspace.json`, independently of queue and review drafts. Navigation is tied to report identity; repeated activation of the same loaded review preserves its fragment, filter and search. Active uncommitted text edits must be applied or cancelled before switching documents. Review uses an incremental fragment model and a virtualized paired list with an editor in the selected card; stable delegates preserve caret and draft state across unrelated updates. Secondary document/translation controls open on demand. Translation actions share the top settings card, leaving the reading area at full available height.

`presentation/session_reconcile.py` can restore a newer tracked Office completion over an older failed/cancelled queue snapshot after restart. A worker verifies the latest matching history record, report and source/output hashes; active work, newer failures, changed state and persisted review drafts veto adoption. It never searches output folders or contacts a provider, and ordinary completed rows retain lazy loading.

`persistence/instance.py` holds an OS-owned file lock before desktop state or CLI translation settings are loaded. One application-data directory has one active desktop/translation writer; read-only inspection and isolated preview workers remain independent. Lock files stay in place, while the OS releases ownership after normal exit or a crash. Review snapshots additionally compare a content fingerprint under a short process lock before atomic replacement. Conflicting saves retain the active editor draft, and the persisted v1 review format stays compatible. Filter reconciliation batches contiguous row insertions/removals and moves retained rows without model resets.

`presentation/preview_controller.py` coalesces local page requests and rejects stale document/page generations. It reads source/output paths independently of translation reports, so completed sessions can preview files after restart. `documents/preview.py` owns a bounded private temporary cache and launches the hidden `preview-worker` command for isolated Qt PDF rasterization. DOCX uses an installed LibreOffice in a private profile with external links/macros disabled and a disposable inactive copy; the original is never rewritten. `presentation/preview_pages.py` installs all page geometry in an incremental model, then publishes only a bounded viewport of raster images. A single virtualized scrolling list keeps original and translated pages aligned and explicitly represents missing pages when counts differ. The isolated metadata command never rasterizes the whole document; the cache pins up to 12 viewport images, limits each raster to four million pixels and bounds temporary disk use to 256 MiB. `DocumentPreview.qml` and `PreviewPagePane.qml` handle viewing modes, zoom and continuous scrolling; sidebar width and preview mode are optional bounded session metadata. Qt PDF's matching Qt WebEngine source archive and dependency notices accompany portable release materials, while LibreOffice is detected externally.

Usage reads/writes and native credential-vault operations run in tracked background work. Completion is checked against the current account/model; editable balance and tariff drafts are not treated as committed values. Connection settings are installed only after persistence succeeds, and vault changes are compensated if preferences cannot be saved. Preference writers merge deltas under a shared lock so an overlapping appearance change is retained.

The usage database is created with mode `0600` on POSIX; opening an older ledger also repairs its permissions before SQLite access. This changes filesystem access only, without rewriting historical accounting.

Local persistence keeps its existing directories, database schemas and canonical report values. Moving a Python module does not invalidate document checkpoints, approved wording, saved reviews or the credential vault. Interface localization applies only when displaying metadata; it does not rewrite document text or stored fingerprints.

Project memory uses explicit, versioned section/worksheet context. `memory/scope.py` resolves actual Word styles and [outline levels](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.outlinelevel?view=openxml-3.0.1), including [style inheritance](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.basedon?view=openxml-3.0.1); `readable_context.py` supplies bounded head/tail facts with full bindings. The same canonical context enters the exact identity and the provider request. Legacy local identities remain available only to a proved, paid editorial migration; old approvals are never copied to a new scope automatically.

`translation/budget.py` measures serialized stage inputs as an application envelope, not a token-window guarantee. `fragments.py` splits supported long paragraphs at safe boundaries, persists private piece drafts/finals inside the file checkpoint and reconstructs the original r/k stream before whole-parent validation. Public segments, memory entries and reports retain parent IDs. `quantities.py` validates only recognized number/unit bindings and complete unit labels; it does not classify arbitrary semantic meaning.

`translation/editorial.py` selects actionable findings and binds private provisional finals/completed-revision markers to the actual source, request context, candidate and translation settings. A targeted revision shares the existing stage budget; only the selected hard-valid final enters public checkpoints or resolves memory futures. Matching machine provenance retains a completed attempt even when the editor returned the same text. Soft findings never reject all paragraph pieces; whole-parent hard failures must also invalidate rejected private editorial results. Human approval stays a separate explicit action.

`translation/recovery.py` reads private failure diagnostics and stores explicitly approved, document-scoped corrections separately from live checkpoints. It binds corrections to the source, extraction profile and checkpoint policy and repeats hard checks before reuse. `presentation/recovery_workflow.py` continues only the selected document with its captured options; the existing Review draft store preserves edits across restarts. Recovery does not export a partial document or publish preferred wording to project memory.

`translation/references.py` checks explicit Word appendix-heading pairs across the document. It reports inconsistent or visually colliding labels without choosing a replacement alphabet or calling a model. Reference findings include a dependency fingerprint of their participating headings; edits to another heading invalidate an old acknowledgement while unrelated review fingerprints remain compatible. `documents/charts.py` binds supported Word chart string caches to exact embedded-workbook cells, groups repeated bindings and updates both copies together. Expanded DOCX results use extraction profile 3; legacy profile-1 review and imports keep their prior surface. Unsupported chart bindings and raster content remain explicit translation-scope limitations.

`providers/request_layout.py` compacts canonical memory contexts only at the wire boundary, retaining all facts and digests. Explicit cache boundaries are gated to documented models on the official OpenAI Chat/Responses connection. `accounting/context.py` carries random operation IDs and bounded stage/retry labels across worker contexts without adding them to prompts or translation-memory identity. Schema-3 usage migrations retain old totals and mark legacy attempts unattributed.

Windows and Linux release builds use PyInstaller's portable directory layout: a root launcher with `_internal` dependencies and resources, delivered together in a ZIP. macOS arm64 builds use a native `.app` bundle with its launcher under `Contents/MacOS` and dependencies/resources inside the bundle; the ZIP includes the complete app. The collected application's complete file/link/directory inventory binds runtime validation and release metadata; a launcher checksum alone cannot validate its support files. Windows workers enter the spec as DATA after dependency analysis. macOS workers are copied as opaque, already frozen native trees after the desktop bundle is built, with their own libraries and signatures retained; the outer app is then signed and its full inventory verified. Linux and macOS ZIPs preserve relative in-bundle symlinks and executable permissions; actual archive extraction is part of release validation. macOS collects the native Keychain backend, uses ad-hoc signing and includes the complete native BabelDOC/OCR/models/Tesseract runtime.

`core.resources.resource_path()` locates the shared QML/catalog assets in source installations and frozen executables. The translation engine routes each PDF independently: text-based PDFs use BabelDOC and the shared glossary; scans pass through `translation/preparation.py` to a hash-bound DOCX before Office translation. The queue retains its original PDF identity and frozen memory session. `translation/handoff.py` coordinates cancellable, serialized ABBYY editor imports without restarting that queue; standalone OCR preparation remains in `presentation/ocr_workflow.py`. ABBYY edition detection never implies automatic-export licensing. The separately frozen OCR package remains under `tools/ocr`; its CPU inference dependencies are isolated from the desktop environment. Windows runtime staging, worker entry points and binary packaging live under `scripts`; see [WINDOWS-RUNTIME.md](WINDOWS-RUNTIME.md) and [MACOS-RUNTIME.md](MACOS-RUNTIME.md).

`documents/worker_process.py` owns direct-PDF workers in a POSIX session or a Windows Job Object. Windows startup assigns the suspended worker before resuming its primary thread, preventing a child-spawn race. Idempotent cleanup also covers descendants whose immediate parent already exited. A draining pipe limits diagnostics on disk to 32 MiB. The 30-minute idle watchdog excludes pauses, active responses and queued provider pacing/cooldown waits; these activity snapshots contain no request text or credentials.

`persistence/prepared.py` stores explicit completed-OCR checkpoints and bounded worker/resource identities; it never searches output folders for a similarly named document. Every reuse validates both artifacts and their source binding before provider work. `documents/ocr_policy.py` is the common provider-selection policy, and `ocr_diagnostics.py` maps only known findings. `settings/connection.py` supplies a mode-aware effective endpoint shared by credentials, requests, pacing, usage and translation profiles. Legacy credentials/account aliases require a known saved-profile identity; paid translations additionally require an unchanged effective request target.

Run `uv run ruff check .` and `uv run pytest` after changing package boundaries. Build and smoke-test the actual executable after import or resource-path changes; a passing source test suite does not prove that a frozen binary contains its dynamic dependencies.

Tests follow behavior boundaries. Pure validators retain distinct malformed-input, numeric, formatting and accounting cases; HTTP integration tests verify representative failures for each provider rather than repeating the entire validator matrix. Desktop tests exercise document work and live settings state, including language and appearance changes. Shared offline providers and wait helpers live in `tests/support.py`, and reusable fixtures in `tests/conftest.py`; test modules do not import one another. Extend the existing behavior test when fixing a regression. Tests that only assert source spelling, obsolete internal helpers or a second copy of an already covered workflow add maintenance without protecting another behavior.

The default `uv run pytest` command runs the complete offline suite. Use `uv run pytest --durations=30` to find slow setup, execution and teardown before adding exclusions or removing useful checks. Case counts include parameterized inputs and do not measure independent features or translation quality.

The workspace settings restrict Python environment discovery to the desktop and OCR virtual environments, and exclude generated Windows/Wine, model and build trees from editor indexing. Wine prefixes contain filesystem links and must not be recursively searched as project source.
