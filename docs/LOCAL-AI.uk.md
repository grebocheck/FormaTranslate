# Локальний AI у FormaTranslate

FormaTranslate може надсилати переклад на мовну модель, яка працює на вашому комп’ютері через **LM Studio** або **Ollama**. Сервер і модель перекладу встановлюються окремо: у Windows-пакеті Forma є OCR та PDF-рушії, але немає LM Studio, Ollama чи універсальної мовної моделі для перекладу.

Для першого налаштування на Windows зручно скористатися графічним інтерфейсом LM Studio. Нижче також є варіант з Ollama. В обох випадках Forma підключається до OpenAI-сумісного API у режимі `chat`.

## LM Studio: запуск на Windows

1. Встановіть [LM Studio з офіційного сайту](https://lmstudio.ai/download). Перевірте [вимоги до системи](https://lmstudio.ai/docs/app/system-requirements).
2. У вкладці **Discover** завантажте мовну модель, яка підтримує ваші мови та виконання інструкцій — зазвичай із позначкою **Instruct** або **Chat**. Embedding-модель призначена для пошуку, а не для такого перекладу. Для Windows обирайте формат, який пропонує встановлений рушій LM Studio; почніть із варіанта, що вміщується у доступну пам’ять.
3. У **Chat** завантажте модель у пам’ять і дочекайтеся готовності. Коротко перевірте переклад у самому LM Studio. [Офіційний початок роботи](https://lmstudio.ai/docs/app/basics) описує завантаження та вибір моделі.
4. Відкрийте **Developer** і ввімкніть **Start server**. Типова адреса сервера — `http://localhost:1234`. Для роботи Forma на цьому самому ПК достатньо локального доступу; **Serve on Local Network** вмикати не потрібно. [Запуск API](https://lmstudio.ai/docs/developer/rest/quickstart), [параметри сервера](https://lmstudio.ai/docs/developer/core/server/settings).
5. Залиште сервер запущеним і налаштуйте Forma за таблицею нижче. Якщо змінили порт у LM Studio, вкажіть цей порт і у Forma.

## Значення у налаштуваннях Forma

Відкрийте **Налаштування** й виберіть **LM Studio (локально)** або **Ollama (локально)**. Пресет заповнить адресу, протокол `chat`, формат `auto` та обмеження один документ / один запит. Поля моделей перекладу й редактора очистяться, щоб старі хмарні моделі не залишилися в локальному підключенні. Сам вибір пресету лише змінює поля: він не встановлює сервер, не завантажує модель, не робить запитів і не зберігає налаштувань.

| Поле Forma | LM Studio | Ollama |
| --- | --- | --- |
| **Адреса API** | `http://localhost:1234/v1` | `http://localhost:11434/v1` |
| **Модель перекладу** | Точний ідентифікатор моделі зі списку сервера | Точне ім’я встановленої моделі разом із тегом, якщо він є |
| **API-ключ** | Порожньо, якщо сервер не вимагає автентифікації; інакше токен LM Studio | Порожньо для звичайного локального сервера |
| **Додаткові параметри підключення → Протокол API** | `chat` | `chat` |
| **Формат відповіді** | `auto` для початку | `auto` для початку |
| **Окрема модель редактора** | Залиште порожнім — та сама модель | Залиште порожнім — та сама модель |

В адресі потрібне саме закінчення **`/v1`**. Нативні адреси LM Studio `/api/v1/chat` і Ollama `/api/chat` використовують інші протоколи. Для цього сценарію обирайте `chat`, навіть якщо сервер також рекламує інші сумісні API. [OpenAI-сумісні адреси LM Studio](https://lmstudio.ai/docs/developer/openai-compat), [Ollama](https://docs.ollama.com/api/openai-compatibility).

Натисніть **Оновити моделі**. Це читає каталог сервера через `GET /v1/models`, без запиту перекладу. Виберіть саме мовну модель або введіть її ідентифікатор вручну. Назва файла на диску чи заголовок картки моделі можуть відрізнятися від API-ідентифікатора. У LM Studio список за ввімкненого Just-In-Time loading може містити й завантажені на диск моделі, які ще не перебувають у пам’яті. [Каталог LM Studio](https://lmstudio.ai/docs/developer/openai-compat/models).

Якщо сервер має інший хост або порт, змініть **Адресу API** у пресеті або скористайтеся **Власним підключенням** і значеннями з таблиці. Власне підключення зберігає поточні поля: за ручного переходу замініть стару модель перекладу на локальну й очистьте **Окрему модель редактора**, якщо там залишилася хмарна назва.

Forma не вимагає непорожнього ключа для цих локальних адрес. У LM Studio автентифікацію можна окремо ввімкнути через **Developer → Server Settings → Require Authentication**; тоді створіть токен через **Manage Tokens** і внесіть його в **API-ключ** Forma. [Автентифікація LM Studio](https://lmstudio.ai/docs/developer/core/authentication). Звичайний локальний Ollama не вимагає ключа; в прикладах із клієнтом OpenAI значення `ollama` є умовним і сервер його ігнорує. [Автентифікація Ollama](https://docs.ollama.com/api/authentication).

Натисніть **Зберегти**, дочекайтеся повідомлення про збереження, потім **Перевірити підключення**. Ця кнопка виконує коротку генерацію JSON обраною моделлю. Перший запит може тривати довше через завантаження моделі.

## Ollama: альтернативний сервер

1. Встановіть [Ollama для Windows](https://ollama.com/download/windows) і відкрийте застосунок. За [офіційною інструкцією](https://docs.ollama.com/windows) він працює у фоні та надає локальний API на порту `11434`.
2. Виберіть у [каталозі Ollama](https://ollama.com/library) придатну для ваших мов локальну Instruct/Chat-модель. Завантажте її через застосунок або командою `ollama pull` із точним іменем із каталогу. Інтернет потрібен для встановлення й отримання ваг моделі.
3. У PowerShell команда `ollama list` показує імена наявних моделей. Якщо сервер уже працює у фоні, ще один `ollama serve` запускати не потрібно.
4. У Forma виберіть **Ollama (локально)**, натисніть **Оновити моделі** й виберіть встановлену модель або введіть точне ім’я з `ollama list`. Потім натисніть **Зберегти** та **Перевірити підключення**.

Для локального перекладу обирайте модель, яка справді виконується на ПК. Ollama може звертатися до хмарних моделей навіть через локальну адресу сервера; сам `localhost` цього не виключає. За потреби вимкніть його хмарні функції через `disable_ollama_cloud` або `OLLAMA_NO_CLOUD=1` та перезапустіть Ollama, як описано в [офіційному FAQ](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features). Це налаштування Ollama, а не Forma.

## Перша перевірка перекладу

Після успішної перевірки підключення відкрийте **Текст і фото** та перекладіть короткий приклад:

> Потужність насоса — 12,5 кВт. Не вмикайте його без води.

Перевірте мову результату, число, одиницю вимірювання та заперечення. Далі перекладіть копію невеликого DOCX із заголовком, таблицею й кількома абзацами. Перегляньте **Перевірку** та відкрийте готовий файл. Успішна відповідь на тест підключення підтверджує лише короткий запит, а не якість перекладу чи надійність роботи з великим документом.

## JSON і сумісність моделі

Для Office-перекладу Forma очікує JSON із масивом `segments` та полями `id` і `text`; для глосарія — масив `terms` із `source` і `target`. Модель також має зберігати службові позначки форматування й захищені значення. Звичайного вміння відповідати в чаті для цього недостатньо.

LM Studio документує JSON Schema через `response_format` у `/v1/chat/completions`; здатність конкретної моделі працювати зі структурованими відповідями треба перевірити. [Structured Output у LM Studio](https://lmstudio.ai/docs/developer/openai-compat/structured-output). Ollama також документує [структуровані відповіді](https://docs.ollama.com/capabilities/structured-outputs) і поле `response_format` у [OpenAI-сумісному API](https://docs.ollama.com/api/openai-compatibility).

| Формат у Forma | Поведінка |
| --- | --- |
| `auto` | Починає з JSON Schema; за явної помилки непідтримуваного формату може перейти до `json`, потім `plain`. Узгодження може зробити додаткові запити. |
| `strict` | Запитує відповідь за JSON Schema; автоматичного переходу до слабшого режиму немає. |
| `json` | Запитує JSON-об’єкт і передає потрібну схему в інструкції. |
| `plain` | Не задає серверу `response_format`, але все одно вимагає JSON за схемою в інструкції. Це не режим довільної текстової відповіді. |

Якщо сервер відхиляє JSON Schema, спробуйте `json`. Якщо сервер не підтримує й цей параметр — `plain`. Якщо модель повертає пояснення, пошкоджений JSON чи втрачає позначки, спробуйте іншу придатну модель; перемикання формату не гарантує виправлення. Перевірки чисел, кодів і форматування у Forma продовжують діяти.

## Пам’ять, швидкість і редактор

У **Швидкість і ліміти → Змінити** почніть із таких значень:

| Параметр | Початкове значення |
| --- | --- |
| **Документів одночасно, 1–4** | `1` |
| **Запитів до API загалом, 1–16** | `1` |
| **Запитів за хвилину, 0 — без обмеження** | `0`; додайте обмеження лише якщо хочете паузи між запитами |
| **Очікування відповіді, с** | Наприклад, `300`, якщо локальна генерація повільна |
| **Ліміт вихідних токенів** | `0` — початковий варіант без явного ліміту від Forma |
| **Рівень міркування** | **За замовчуванням**; це не універсальний перемикач thinking для всіх локальних моделей |

Мала квантована модель потребує менше пам’яті, але може гірше перекладати й утримувати структуру. Більша модель або довший контекст потребують більше RAM/VRAM. Обирайте за доступною пам’яттю, підтримкою мов і власним прикладом документа; саме число параметрів не доводить якість. LM Studio має [оцінку пам’яті перед завантаженням](https://lmstudio.ai/docs/cli/local-models/load) через `lms load --estimate-only`.

Контекст має вмістити інструкції, оригінал, сусідній текст, глосарій, редакторську чернетку й відповідь. **Ліміт вихідних токенів у Forma не задає розмір контексту сервера.** Змінюйте його в налаштуваннях завантаження моделі LM Studio або в налаштуваннях Ollama. У Ollama перевірити фактично виділений контекст і використання CPU/GPU можна через `ollama ps`; більший контекст збільшує потребу в пам’яті. [Контекст Ollama](https://docs.ollama.com/context-length). Для його OpenAI-сумісного API також описано налаштування моделі через `Modelfile` із `PARAMETER num_ctx`; Forma цей параметр окремо не надсилає. [Зміна контексту через Modelfile](https://docs.ollama.com/api/openai-compatibility).

Підвищуйте паралельність лише після стабільної роботи з одним запитом. Дві моделі, великий контекст, OCR і PDF-аналіз можуть одночасно займати пам’ять. Якщо відповідь дуже повільна, перевірте завантаження CPU/GPU та пам’ять у сервері, зменште модель або контекст у межах потреб документа.

Редакторська перевірка та додаткові виправлення теж обчислюються локально й потребують часу. Поле **Окрема модель редактора** можна залишити порожнім або вказати іншу модель, яку обслуговує **цей самий сервер**. Окремої адреси для редактора немає: поєднання хмарного перекладача й локального редактора через два різні сервери тут не налаштовується. Перемикання моделей може додавати час їх завантаження.

## Фото та PDF

Для **Текст і фото → Фото** потрібна модель з підтримкою зображень — **Vision** — і сумісний спосіб передавання зображень у сервері. Звичайна текстова модель не розпізнає фото. Наявність моделі у списку не підтверджує підтримку зображень; перевірте її картку й окремий тест із фото. [Фото у Forma](TEXT-AND-PHOTOS.md), [Chat Completions LM Studio](https://lmstudio.ai/docs/developer/openai-compat/chat-completions), [Vision у сумісному API Ollama](https://docs.ollama.com/api/openai-compatibility).

Розпізнавання сканованого PDF у DOCX виконує **окремий OCR-рушій**. Він не використовує обрану мовну модель; локальний AI отримує текст уже після OCR. Прямий переклад текстового PDF потребує **BabelDOC**. Повний Windows-пакет містить ці рушії й їхні ресурси; для Linux/встановлення з коду вони готуються окремо. Встановлення LM Studio або Ollama цього не замінює. Перевірте власний PDF окремо: можливості OCR, верстки й локальної моделі не дають гарантії повноти чи точності. [Налаштування PDF/OCR](PDF.md).

## Якщо не працює

| Симптом | Що перевірити |
| --- | --- |
| Немає з’єднання | Сервер запущений; порт і адреса збігаються; у Forma є `/v1`. |
| HTTP 401 | У LM Studio увімкнено автентифікацію: потрібен його токен. Для звичайного локального Ollama ключ не потрібен. |
| HTTP 404 або модель не знайдена | Точний API-ідентифікатор, тег моделі, адреса та `chat`; очистьте стару хмарну модель редактора. |
| Порожній список моделей | Завантажте модель, перевірте сервер; ідентифікатор можна ввести вручну. |
| Помилка JSON або `response_format` | Узгодьте формат відповіді за розділом вище; перевірте придатність моделі. |
| Помилка контексту або обірвана відповідь | Контекст сервера, пам’ять, ліміт відповіді та журнал сервера. Почніть із короткого документа. |
| Помилка параметра `max_completion_tokens` | Спробуйте **Ліміт вихідних токенів = 0**; підтримка явного параметра залежить від сервера. |
| Зависоке навантаження | Один документ і один запит; модель, контекст та одночасно запущені OCR/PDF-завдання мають уміщуватися в пам’ять. |

## Що перевірено

Поля та поведінку звірено з кодом Forma; офіційні документи серверів переглянуто **2026-11-12**. Офлайн-тести Forma перевіряють OpenAI-сумісний запит Chat Completions із JSON Schema, приймання відповіді та узгодження `json_schema → json_object → plain` у режимі `auto` на імітованих відповідях. Окремі тести каталогу перевіряють `/v1/models` і локальне підключення без авторизації. Це перевірка протоколу програми, а не сертифікація будь-якої версії LM Studio/Ollama чи мовної якості їхніх моделей. Під час підготовки цієї інструкції сервери й моделі не встановлювалися та не запускалися.

Після встановлення сервера перевірте власну модель спочатку на короткому тексті та DOCX. Якщо потрібна робота без мережі, заздалегідь завантажте всі моделі й PDF/OCR-ресурси та повторіть цей тест із вимкненою мережею.
